version: "2.27.0"
date: "2026-08-17"
title: "Contacts directory and Respond.io ticket automation"
summary: "SIMS now has a single record for a merchant-side person. A contact carries multiple phone numbers and maps to either one outlet or an entire franchise, across any number of franchises, so a franchise owner covering six outlets is one record instead of six. On top of that directory, Respond.io conversations routed to Merchant Success now create, assign, and close SIMS tickets automatically through n8n, resolving the customer to that same shared contact and auto-linking the outlet whenever the mapping is unambiguous."
new:
  - title: "Contacts directory under General"
    detail: "A new Contacts page lists every merchant-side person with their phone numbers, email, role, and how many outlets or franchises they represent. Search matches name, email, or any phone number in any format — searching \"016 220\" finds \"+60 16-220 7781\" — and franchise, outlet, and role filters persist across refreshes. Selecting a row opens a summary panel with the contact's mappings; the full contact page adds editing, deletion, and mapping management. Access is a new /contacts key, assignable to any department from User Management."
  - title: "Map a contact to one outlet or a whole franchise"
    detail: "A mapping is either outlet-specific or franchise-wide, and a franchise-wide mapping covers every outlet under that franchise — including outlets opened later. One contact can hold any number of mappings mixed freely across franchises. SIMS blocks redundant mappings and explains why: adding an outlet already covered by a franchise-wide mapping names the mapping that covers it, and going franchise-wide over existing outlet mappings tells you to remove them first."
  - title: "Duplicate phone or email blocks creation and offers the existing contact"
    detail: "Submitting a phone number or email that already belongs to another contact blocks the save and names that contact as a link, so staff open the existing record instead of creating a second one. A submission that collides on the phone against one contact and on the email against a different one surfaces both. The check runs inside the same transaction as the insert, so two people submitting the same number at the same moment cannot both get through."
  - title: "An outlet's contacts on the merchant page"
    detail: "Opening a franchise in Merchants and selecting an outlet now lists the contacts mapped directly to that outlet plus the contacts mapped to the franchise as a whole, each linking through to its contact page."
  - title: "Shared contact picker for Sales, Renewal & Retention, and Merchant Success"
    detail: "A single search endpoint and picker component backs contact lookup across modules, optionally scoped to a franchise or outlet — and scoping to an outlet still surfaces franchise-wide contacts, since those represent every outlet under it. Soft-deleted contacts never appear. Attaching a chosen contact into a Lead, Deal, Ticket, or Invoice is scoped per module and not part of this release."
  - title: "Respond.io conversations create, assign, and close tickets automatically"
    detail: "Three n8n workflows now call a new SIMS endpoint. Tagging a Respond.io contact with the configured Merchant Success routing tag creates an open ticket; reassigning the chat in Respond.io updates the ticket's MS PIC by matching the assignee's email to a SIMS user; closing the conversation resolves the ticket and stamps its closure time. Every call is logged whether it was processed, ignored, rejected, or a no-op, and n8n's retries cannot create duplicates."
  - title: "Tickets auto-link to an outlet through the contact directory"
    detail: "SIMS resolves an inbound Respond.io contact to a SIMS contact by stored Respond.io id, then phone, then email, auto-creating one when nothing matches. If that contact has exactly one outlet mapping the ticket links to it outright. If the mapping is franchise-wide, the ticket's franchise is pre-filled read-only and the agent only supplies the outlet id. Anything ambiguous is flagged for manual linking with no guess. Confirming an outlet by hand teaches the directory, so the next ticket from the same person links itself — unless a franchise-wide mapping already covers it, in which case no redundant mapping is stored."
  - title: "Integrations settings page"
    detail: "A new Integrations page under General holds the Merchant Success routing tag, the shared secret, and the inbound event log. Secrets are stored only as a hash and shown exactly once when issued, so there is no reveal — rotate to get a new one. Rotation keeps the previous key working as a grace window so n8n can be updated without dropping events."
improved:
  - title: "Ticket franchise and outlet names resolve from the franchise alone"
    detail: "Editing a ticket previously only re-resolved the franchise and outlet names when both ids were present, so a ticket with a known franchise and an unknown outlet showed neither name. It now resolves on the franchise alone. The duplicated resolver in the ticket and support-form routes has been consolidated into one shared function."
fixed:
  - title: "Outlet ids no longer truncate on tickets and ClickUp task requests"
    detail: "tickets.oid and clickup_task_requests.oid were VARCHAR(2) and tickets.fid was VARCHAR(4) — far too narrow for real 5-digit ids, which meant a value was either silently truncated or rejected outright depending on the database's strict mode. All four columns are now VARCHAR(120), matching the merchant cache they refer to. Audit for already-truncated values before applying migration 025; the release notes for the migration include the query."
  - title: "Clearing a ticket's franchise or outlet stores an empty value"
    detail: "The ticket editor wrote an empty string instead of a null when a franchise or outlet id was cleared, leaving a mixed column that analytics queries had to work around with per-query guards. Cleared fields are now stored as null."
  - title: "ClickUp task requests no longer fail on an unlinked ticket"
    detail: "Requesting a ClickUp task for a ticket with no outlet would fail against a NOT NULL column with an opaque server error. The action is now blocked up front with a message asking you to link the outlet first — a ClickUp task with no outlet was not actionable anyway."
breaking_changes: "Migrations 024 and 025 must be applied in order before deploying; 025 references the contacts table created in 024. Migration 025 widens tickets.fid/tickets.oid and clickup_task_requests.fid/oid to VARCHAR(120) and makes the ticket columns nullable — audit for values already truncated by the old widths first (SELECT id, fid, oid FROM tickets WHERE CHAR_LENGTH(oid) = 2 OR CHAR_LENGTH(fid) = 4). A 2-character oid cannot be recovered from the ticket row alone. The new /contacts and /integrations access keys must be granted in User Management before non-Super-Admin users can see either page."
