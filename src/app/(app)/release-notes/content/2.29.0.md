title: "Tickets move to In Progress when an agent replies"
summary: "A new Respond.io event tells SIMS when a Merchant Success agent sends their first outgoing message on a conversation, and the ticket moves from Open to In Progress on its own."
new:
  - title: "First agent reply advances the ticket"
    detail: "SIMS now accepts Respond.io's outgoing-message event alongside the tag, assignee, and conversation-closed events it already handled. When an agent sends the first outgoing message on a conversation, the contact's open ticket moves from Open to In Progress and the change is written to the ticket's history, attributed to the integration. Being assigned a ticket no longer looks the same as working on it in the board and in the analytics that read status."
  - title: "Later replies leave the status alone"
    detail: "Only a ticket still sitting at Open is advanced. Every later message on the same conversation is recorded as a no-op, so a ticket an agent has moved to Pending Customer is never dragged back to In Progress because they answered again, and a resolved ticket is never reopened."
improved:
  - title: "Message Sent shows up in the integration event log"
    detail: "General → Integrations lists the new event as New Outgoing Message, with the same processed / ignored / no-op / failed outcomes as the other three. A fourth importable n8n workflow, sims-respondio-message-sent.json, ships in the n8n folder with setup notes covering which message counts. Its trigger is pinned to messages sent by a team member, so bot, AI Agent, and workflow auto-replies never make a ticket look picked up."
