---
version: "3.0.0"
date: "2026-08-27"
title: "Server-side authorization boundary"
summary: "Authentication and page-access checks now run on the server before any data is queried — a forged cookie or a missing access key can no longer reach ticket, sales, CSAT, or merchant data. Several API routes that only checked for a login now also check the caller's page access and role."
new:
  - title: "Server-side session and page-access guards"
    detail: "Every server-rendered analytics and overview data module now authenticates the session and checks the page-access key before running a single query, redirecting to the login page or the general overview otherwise. The client-side gate remains, but purely as a navigation nicety — the boundary is on the server."
  - title: "One API authorization helper"
    detail: "All per-module API auth helpers are now one-line wrappers around a single resolveApiUser helper, so the Super Admin bypass, status codes, and error messages live in exactly one place and can be unit-tested without a database."
improved:
  - title: "The general overview degrades instead of leaking"
    detail: "Each section of the general overview (tickets, sales, merchants, CSAT) now checks the viewer's access key and shows its existing 'data unavailable' state instead of querying data the viewer has no key for."
  - title: "Middleware covers every page by default"
    detail: "The login redirect now uses a negative matcher, so newly added pages are covered automatically and fail closed instead of relying on a hand-maintained prefix list. API routes are deliberately excluded so cron and webhook endpoints keep working."
  - title: "No more session-check flash"
    detail: "The app layout passes the server-resolved user to the client gate, so navigating no longer shows a 'Checking session...' flash on every page."
fixed:
  - title: "Under-authorized API routes now check page access and role"
    detail: "Ticket category management, ticket updates, ticket and merchant exports, the PLUS tools, the Google Places proxy, ClickUp task requests, and onboarding appointments now require the matching page-access key. Deleting ticket categories, running a manual merchant import, and running a manual ClickUp sync additionally require the Admin role. Cron secrets are now compared in constant time."
breaking_changes:
  - title: "API calls without the matching page access now return 403"
    detail: "Users whose accounts lack the relevant page-access key (or the Admin role, for the destructive endpoints above) will receive 403 Forbidden from these routes where they previously succeeded with any valid login. Grant the corresponding page access in User Management if someone legitimately needs an affected endpoint."
---
