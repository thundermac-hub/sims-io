---
version: "2.30.0"
date: "2026-08-27"
title: "Closing a ticket sends the CSAT survey automatically"
summary: "When a Merchant Success agent resolves a ticket that came in through Respond.io, SIMS now sends the merchant their CSAT link straight back into the same conversation — no share button to remember."
new:
  - title: "CSAT link goes out on close"
    detail: "Moving a Respond.io ticket to Resolved mints the survey link and sends it as a WhatsApp message in the conversation the merchant already used. The wording is identical to the manual share message, and the link carries the same three-day expiry, so nothing changes for the merchant except that it now arrives every time. The send is recorded on the ticket as CSAT Link Shared, so the ticket's CSAT status shows Send and the audit trail shows who closed it."
  - title: "Never two surveys for one ticket"
    detail: "An agent who shared the link by hand before closing does not trigger a second send — SIMS checks the ticket's own share history first, including links shared before this release. Re-saving an already-closed ticket sends nothing either, since only the move into Resolved fires it."
improved:
  - title: "A failed send tells you, instead of failing the close"
    detail: "If the message cannot go out, the ticket still closes — that part already succeeded — and the toast says the CSAT link could not be sent and to share it manually. The reason is written to the ticket's history as CSAT Auto-Send Failed and shows up in Merchant Success → Audit Trail, and the ticket's CSAT status stays Not Sent so the share button is the obvious next step."
  - title: "Tickets without a Respond.io conversation are left alone"
    detail: "Support-form and manually created tickets have no Respond.io conversation to send into, so they are skipped and keep using the share button on the ticket page exactly as before. The automatic send also stays off entirely until the outbound webhook is configured, so nothing changes in an environment that has not been set up for it."
fixed:
  - title: "One place decides what a CSAT link looks like"
    detail: "Token issuing moved into a shared helper used by both the manual share button and the automatic send, so the link's format, expiry, and the retiring of a superseded link can no longer drift between the two paths."
