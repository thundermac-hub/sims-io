date: "2026-08-18"
title: "Contact mapping fixes"
summary: "Adding a contact mapping now picks the outlet from a list of the franchise's own outlets instead of asking for an id, removing a mapping asks for confirmation first, and the merchant lookup endpoint resolves an outlet id when one is supplied alongside a franchise id."
improved:
  - title: "Pick the outlet from a list instead of typing its id"
    detail: "The contact mapping dialog now loads the franchise's outlets once the franchise id resolves and offers them in a dropdown, each showing the outlet name alongside its id. An outlet id only means anything relative to a franchise, so a typed id was easy to get wrong and slow to verify. Changing the franchise id clears any outlet already selected, since a selection made against a different franchise would otherwise be submitted as-is."
  - title: "Removing a mapping asks first"
    detail: "The remove button on a contact's mapping fired immediately. It now opens a confirmation that names the exact outlet or franchise being unmapped and spells out the consequence — that inbound conversations from the contact will stop linking to it automatically — while making clear the contact and its other mappings are untouched."
fixed:
  - title: "Merchant lookup resolves an outlet supplied with a franchise id"
    detail: "Passing both fid and oid to /api/merchants/lookup silently dropped the oid, so callers that sent both — the contact mapping dialog and the ticket outlet-link panel — reported \"no outlet found\" even for a valid outlet. The outlet is now resolved and returned, scoped to the matched merchant so an outlet belonging to a different franchise is correctly reported as not found rather than silently accepted. The franchise itself also now matches on external id as well as fid."
