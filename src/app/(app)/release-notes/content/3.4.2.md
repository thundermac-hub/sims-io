title: "Review fixes: rate-limit keying, attachment scoping, legacy files"
summary: "A review pass over the hardening branch fixed a rate-limit bypass, scoped shared attachment reads to the pages a user can actually see, kept legacy files viewable, and removed a batch of duplication."
fixed:
  - title: "Rate limits key on the unforgeable client IP"
    detail: "Behind the trusted proxy, the client IP is now taken from the rightmost x-forwarded-for entry (the one our proxy appends) instead of the leftmost, which arrives inside the client's own request — previously an attacker could rotate a forged header to dodge every per-IP limit."
  - title: "Shared attachment reads are scoped per page key"
    detail: "The file-view reference check now consults only the record stores the caller's page keys cover, so a tickets key can no longer justify reading onboarding-appointment attachments it never granted."
  - title: "Legacy files stay viewable"
    detail: "Files uploaded before the allowlist existed (GIF, BMP, TIFF, MP4, MOV, TXT) are served with their real content type again — GIF and BMP render inline; SVG deliberately stays a download because inline SVG can carry script. Avatars now cache privately in the browser instead of refetching on every page."
  - title: "Migration splitter drops trailing comments"
    detail: "A migration file ending in a comment no longer sends that comment to MySQL as an empty query, which would have aborted a deploy mid-file."
  - title: "CSAT links survive shared-IP bursts"
    detail: "Survey page loads now get a larger per-IP budget so a batch of merchants behind one carrier NAT can all open their links, while submissions and token probing stay strictly limited."
  - title: "Session revocation is picked up on navigation"
    detail: "The client gate revalidates the session in the background on every navigation (with no loading flash), so a deactivated account is signed out at the next page change instead of at the next full reload. The merchants Import button is now shown only to Admins, matching the server rule."
improved:
  - title: "Less duplication in security-sensitive code"
    detail: "One shared HTML-escaping helper, one constant-time cron-secret check, one extension-to-content-type table, one location-picker access list, and one attachment-ownership check — each previously existed in two to four copies that could drift apart."
