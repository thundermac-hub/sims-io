version: "3.2.0"
date: "2026-08-27"
title: "OAuth gating, CSAT hardening, honest errors, and rate-limit fundamentals"
summary: "The Google Calendar setup flow is locked behind a Super Admin and a kill switch, the CSAT survey endpoints are rate-limited properly and stop exposing customer data, internal error details no longer leak to API clients, and rate limiting refuses misconfiguration and fails closed."
new:
  - title: "Content-Security-Policy in report-only mode"
    detail: "A real CSP now ships on every page in report-only mode: violations show in the browser console for one release before enforcement, so Mapbox, charts, and the theme toggle can be verified without risking a white screen. The framing-protection matcher was also anchored so lookalike paths (e.g. /demoform-archive) are no longer exempt."
  - title: "Boot-time rate-limit configuration check"
    detail: "In production the app now refuses to start without TRUSTED_PROXY and REDIS_URL, because without them every client silently shares one rate-limit bucket per process. Set both in the deployment environment before rolling this version out."
improved:
  - title: "Google Calendar OAuth setup is gated"
    detail: "The refresh-token setup flow now requires a signed-in Super Admin and an explicit GOOGLE_CALENDAR_OAUTH_FLOW_ENABLED=true kill switch (off by default). The token is no longer printed in the browser — it goes to the server logs — and the result page escapes Google's error text and sends no referrer."
  - title: "CSAT survey endpoints hardened"
    detail: "The survey lookup is now rate-limited per IP and per (hashed) link, so iterating tokens no longer earns a fresh budget each time. Expired or submitted links no longer return ticket details, the customer phone number is never returned (the form never showed it), and submissions are validated against the exact EN/BM answer labels with a 2000-character cap on free text."
  - title: "Internal errors stay internal"
    detail: "A dozen API routes that echoed raw exception text (SQL errors, upstream API messages) now log the real error server-side and return a generic message. The public support form keeps its genuine user-facing validation messages."
  - title: "Rate limiting is atomic and fails closed"
    detail: "Counter increment and expiry now run as one atomic Redis script that also self-heals stranded keys, every throttled response carries a Retry-After header, and if Redis is down the affected endpoints return 429 rather than 500 or silently unlimited traffic."
